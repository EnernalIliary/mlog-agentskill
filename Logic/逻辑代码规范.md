# mlog 逻辑代码规范 v1

> 适用范围：手写 mlog、让 AI 生成 mlog、审阅别人给的逻辑、写蓝图里的处理器程序。
> 依据：`Mindustry-Source` 的 `LExecutor.java` / `LStatements.java` / `LogicBlock.java`，
> 以及本仓库 `mlog工作笔记.md` 里被实测推翻过的结论。**规范与源码冲突时，以源码为准，并回来改这份文档。**

## 0. 先定需求，再写第一行

写逻辑前先回答五个问题，答不上就别写：

1. **数量**：处理几个单位 / 几个物品 / 几个目标？上限是多少？
2. **阈值**：什么条件算“够”、算“满”、算“该走”？阈值从游戏机制来，不许自己发明。
3. **失败策略**：目标丢失、单位死亡、内存格被占用、链接没接，程序往哪走？
4. **依赖**：需要哪些方块（处理器型号、内存格、消息块、开关、穹顶）？链接名是什么？
5. **周期**：每 tick 跑几轮？允许的响应延迟是多少 tick？

写进文件头（`#` 注释，导入时会被解析器剥掉，只给人看），并在回复里复述一遍。

## 1. 文件骨架

```mlog
# ===== 头部：用途 / 依赖 / 链接名 / 版本 =====
# 用途：把铜送到核心，核心满则待机
# 依赖：micro-processor；链接 memory1(内存格)、message1(消息块)
# 版本：build 146+；每 tick 2 条指令
# 作者：<名字>  日期：YYYY-MM-DD

# ---- 常量区：只在这里写魔数 ----
set cfg.radius 8
set cfg.minItem 1

# ---- 主循环 ----
ubind @flare
sensor unit.dead? @unit @dead
jump 6 equal unit.dead? 1
...
end
```

- **一段一件事**：常量、绑定、读状态、决策、执行、收尾，顺序固定，别把 `ulocate` 塞进条件分支。
- **每个分支自己收尾**：以 `end` 或一条明确的 `jump` 结束，不允许“顺着掉进”下一段。
- **行号注释**：`jump` 的数字是 0 基语句序号，改一行后面全偏；在每条 `jump` 上方写目标行的用途，例如
  `# -> 12 重新绑定`，交付前逐条数一遍。

## 2. 命名：一律用 `.` 分段

变量名写成 **`域.字段`**，点号是分隔符，不是成员访问。解析器把整个 token 当变量名，实测
`cfg.radius`、`unit.hp`、`ready?`、`crush.damage(/tiles*s)` 都能原样解析、执行、回读。

| 对象 | 规则 | 例 |
|---|---|---|
| 变量 | `域.字段`，全小写，段间用 `.`；域只用下表固定的几个 | `unit.hp`、`core.x`、`tgt.dist` |
| 常量 | 统一 `cfg.` 域 | `cfg.radius`、`cfg.minItem` |
| 坐标 | `.x` / `.y` 表示 tile；要 world 像素加 `.wx` / `.wy` | `core.x`、`tgt.wx` |
| 临时量 | `tmp.` 域 + 单字母，只在相邻 3 行内用 | `tmp.a`、`tmp.d` |
| 布尔 | `.` 分段 + `?` 后缀（与作者现有写法一致） | `unit.dead?`、`core.found?` |
| 带单位 | 单位写进最后一段的括号里，便于人读 | `crush.damage(/tiles*s)` |
| 链接名 | 只用 ASCII、字母开头、不带空格；链接名**不用**点号 | `memory1`、`message1`、`switch1`、`dome` |

固定域表（不要临时造域，一个文件里就这几个）：

| 域 | 含义 |
|---|---|
| `cfg.` | 常量、阈值、开关 |
| `unit.` | 当前 `@unit` 的属性快照 |
| `core.` | 我方/最近核心 |
| `tgt.` | 当前目标（单位或方块） |
| `mem.` | 内存格/跨处理器的值 |
| `cnt.` | 计数器、轮次 |
| `tmp.` | 临时量 |

- **不要用裸 `x` 当变量名**：`jump ... always` 会让汇编器生成一个占位变量 `x`，同名会混；临时量写 `tmp.x`。
- **`cfg.` 是配置面，不是死代码**：`set cfg.count 0`（或 1、8）往往就是给使用者改的开关/阈值。交付时保留、在文件头写清含义与范围；静态检查报“赋值未读”时先确认它是不是参数，别急着删。
- **不要覆盖 `@` 开头的内建名**（`@counter`、`@unit`、`@this`、`@ipt`、`@time`、`@tick`、`@second`）。
- 链接名改一次，所有 `read/write/sensor/control` 的引用都要改；交付时列出链接清单。

## 3. 坐标与单位（最容易错 8 倍）

| 接口 | 输入/输出 | 单位 |
|---|---|---|
| `ucontrol move/approach/stop/pathfind x y` | 输入 | **tile**（内部 `World.unconv` 乘 8） |
| `sensor unit.x @unit @x` / `unit.y` | 输出 | **tile** |
| `ulocate ... outX outY` | 输出 | **tile** |
| `ucontrol within x y r result` | 输入 tile，输出 0/1 | tile |
| `sensor r @unit @range` | 输出 | **tile**（`maxRange / 8`） |
| `radar` / `uradar` | 无坐标参数，从雷达方块/单位自身位置找 | — |
| `op sin/cos` | 参数 | **角度（度）**，不是弧度 |
| `@time` / `@tick` / `@second` | 输出 | ms / tick / s |
| `wait` | 参数 | 秒（浮点） |

- `ucontrol move` 只写 `LogicAI` 的意图，**位移发生在下一 tick 的单位更新**；不要在同一 tick 里期望 `@x` 立刻变。
- 角度用度：`op add tmp.a tmp.a 4` 表示每轮 4°；要弧度先 `op mul tmp.rad tmp.deg 57.2958`。
- 距离比较统一用 tile：`op sub tmp.dx tgt.x unit.x`、`op len tgt.dist tmp.dx tmp.dy`（`len` 是二维长度）。

## 4. 空值与守卫

- 未赋值变量、缺失链接、`sensor` 读不到、`read` 未声明的槽，结果都是 **`null`**，不是 0。
- `null` 参与算术 → `null`；`print null` → 文本 `null`；`jump ... equal X null` 在 `X` 为 `null` 或数值 0 时都成立（`null.num()==0`）。
- **判断“有没有”一律用 `strictEqual 变量 null`**，不要用 `equal`（0 会混进来）。
- 每个外部输入（链接、传感器、内存格）第一次用之前都要守卫：

```mlog
sensor unit.hp @unit @health
jump 0 strictEqual unit.hp null   # 读不到就回开头重绑，别拿 null 去比较
```

- `@dead` 对 `null` 也返回 `1`，所以“死了/不存在”可以一条判断：

```mlog
sensor unit.dead? @unit @dead
jump 0 equal unit.dead? 1
```

- 除零、`logn 0 2`、`sqrt -1` 都静默变 `null`；要么先判，要么接受 null 并守卫。

## 5. 控制流与行号

- `jump N ...` 的 `N` 是 **0 基语句序号**；`jump 0 always` 是回到第一条。
- `end` 把 `@counter` 置 0，等于回到开头；`stop` 停机。
- **改一行就重算全部 `jump`**；生成蓝图/`msch` 后 `jump` 已编译成数字，再插行会错位。
- 目标标签不存在时，游戏把跳转变成 `-1`（静默落下），不会报错——所以交付前用 `mlog.py check` 查。
- **不要用 `wait` 做主要节拍**：`wait` 整段空转，处理器这段时间什么也算不了。常规写法是记一个到期时间，在等待期间继续做别的事：
  ```mlog
  op add cfg.timer @time 500      # 到期时刻 = 现在 + 500ms
  # ... 等待期间可以继续读传感器/算目标/控制别的单位 ...
  jump <下一段> greaterThan @time cfg.timer
  ```
  只有“这一段确实没事可做、只想把本 tick 剩余的 ipt 让出去”时才用 `wait`（或 `printflush @wait`）。
- 每条 `jump` 的目标行上方写注释；不要跳到 `sensor/set/ubind` 这类有副作用的行上。

## 6. 预算与节拍

| 处理器 | ipt | 每秒语句 |
|---|---|---|
| micro | 2 | 120 |
| logic | 8 | 480 |
| hyper | 25 | 1500 |
| world | 8（可配到 1000） | 480+ |

- 预算按**执行到的语句数**算：`jump` 也是 1 条，不免费。
- `wait`、`stop`、`printflush @wait` 会 `yield`，提前结束本 tick；`jump 0 always` 不会。`yield` 省的是本 tick 的剩余 ipt，但等待期间处理器完全不动——需要继续算东西时用 `@time` 到期判定，不要 `wait`。
- 估算最坏路径用 `python mindustry-blueprint/tools/mlog.py check <f> --cost`；报告里的“最坏指令数 / 折合秒数”按 ipt=2 给，换处理器自己乘。
- 每 tick 只做“必须现在做”的事：扫描、决策可以隔 N tick 做一次（用计数器），别每 tick 全量遍历。

## 7. 单位控制

- **先 `ubind`，再 `ucontrol/uradar/ulocate`**；`@unit` 初值是 `null`，不绑就静默无效。
- **`ubind` 的两种参数不是一回事**：给**单位类型**（`ubind @flare`）时按该类型的内部缓存顺序**轮转**，每调用一次绑下一个，不需要自己维护下标，但队列增减会跳过/重复；给**具体单位**（`ubind unit.target`）时直接绑那一个，条件是同队（或 world processor）且 `logicControllable`，否则绑成 `null`。
- 存活用 `@dead == 1`（死了或不存在）；归属用 `sensor unit.ctrl @unit @controller` 后比较 `@this`。
- 循环里每轮重新 `ubind`（环形推进），不要假设“绑一次管到底”。
- `ucontrol` 只对当前 `@unit` 生效；`LogicAI` 的控制有 10 秒超时，超时后单位停住、不会回退阵营 AI——长时间任务要周期性重发控制。
- 射程保持自己算：`@range` 是 tile 的 `maxRange`，`ucontrol target` 的引擎不按射程过滤；停在 `range - margin` 是程序的责任。
- `within` 的第 4 参是结果，不是输入。
- **取放料**：`ucontrol itemTake core1 @silicon 20 0 0` / `ucontrol itemDrop core1 20 0 0` 只对当前 `@unit` 生效，要求同队、目标有 `items` 且单位在 `45 world + 方块半宽` 内（约 6 格），远了静默无效；两次转移之间有 `LogicAI.transferDelay`，连续取放要等它过去。取完用 `sensor unit.items @unit @totalItems` 断言，别假设成功。

## 8. 内存与跨处理器

- 内存格按槽位读写：`read mem.v cell1 0` / `write mem.v cell1 0`；格子容量 64，内存库 512。
- 跨处理器按名读：`read mem.v processor1 "slot"`；**槽必须由对方先声明**，未声明的槽读回 `null`、写是静默空操作。
- **处理器自己的变量也能按名存取**：`read mem.v @this "slot"` / `write mem.v @this "slot"`。这是“把处理器当存储”的正式写法，模拟器已支持；名字是**字符串**，不是变量名——写一个程序里从未出现过的名字是静默空操作（`LogicBlock.write` 找不到变量就直接 return），`check` 会报 INFO。数字地址 `read mem.v @this 0` 取的是第 0 个**链接**，不是变量。
- **声明不等于赋值**：汇编器的 `vars.get(name, true)` 会在名字第一次出现时创建变量（初值 null），任何语句都算，不要求 `set`。`draw triangle a b c d e f` 就是一次声明 6 个的紧凑写法（画出来的是 0,0 退化三角形，但变量列表里有了这 6 个名字）。所以判断“未声明”只能看**全文是否出现过这个字符串**；只声明未赋值的名字读到的是 null（不是 0），算术上要自己保证先赋值。
- 链接名必须真实连接。`.msch` 自带链接表；裸 `.mlog` 没有链接表，`tools/mlogsim.py --links auto`（默认）会给它读而不赋值的名字（`cell1`、`bank1`、`message1`、`dome1`）在处理器旁放一个同类方块并接上，`--links off` 才是原样（`null`）。
- **链接名不是方块全名**：游戏用 `LogicBlock.getLinkName()` 取方块名最后一个连字符段再加序号。`silicon-arc-furnace` 的链接是 `furnace1`、`furnace2`…，写 `silicon-arc-furnace1` 永远不会绑定（语句静默无操作）；`check` 对带 `-` 的名字报 `link-name-hyphen` ERR。同理，`large` 结尾的方块去掉 `large` 再命名。
- 读核心库存没有内置变量，默认写法是“先绑单位，再 ulocate”：
  `ubind @mono` → `ulocate building core false @copper core.x core.y core.found? core` → `sensor n core @silicon`、`sensor cap core @itemCapacity`。
  `ulocate` 的核心坐标是 tile；`core.found?=0` 表示没找到（没有核心、或索引里没有），比较前先判它。
- 多处理器共享状态时，先定“谁写、谁读、什么顺序”，别两个处理器同时写同一格。
- 用 `@links` / `getlink` 遍历链接时，注意顺序不稳定，按名字匹配而不是按下标。

## 9. 特权语句与世界处理器

`weathersense`、`weatherset`、`setrule`、`message`、`cutscene`、`effect`、`fetch`、`sync`、`getblock`、`setblock`、`spawn`、`status` 等是 **privileged**：

- 只能放 **world processor**（`--processor auto` 会自动识别）；
- 放进 micro/logic/hyper 时，解析器把整行换成 `InvalidStatement`，**静默消失，不报错**；
- 需要世界处理器时，ipt 是 8，预算按 8 算；不要指望它在微型处理器上“至少不生效”。

**特权内置变量**（同样是 privileged，但不会删行，只会静默变成 null）：`@server`、`@client`、`@clientLocale`、`@clientUnit`、`@clientName`、`@clientTeam`、`@clientMobile`、`@clientMusicPlaying`。普通 micro/logic/hyper 里读它们得到的是 **null 常量**，不报错；只有 world processor 能拿到真值（`GlobalVars.get(name, privileged)` 在非特权时直接返回 `"null"`）。所以**不要用 `@clientUnit` 做“玩家单位”判断**：普通处理器里它永远是 null；单机/服务器都一样。

## 10. 打印、注释与调试

- `#` 注释只在源码/工具里有效，进游戏被剥掉；游戏内可见的说明用 `print`。
- `print` 只写缓冲，`printflush message1` 才显示；缓冲区上限 **400 字符**，超了截断。
- `printflush null` 会清空缓冲但不显示——可以当“丢弃输出”用。
- 调试信息集中在文件尾部或独立消息块，交付前删掉或加开关（`sensor cfg.debug? switch1 @enabled`）。

## 11. 生成蓝图时的额外规则

- 蓝图里的 `jump` 是已编译的行号；**先定稿逻辑，再生成**，之后不要再插行。
- 方块坐标是**中心格**（`--with-block` 也一样）；`msch` 只存建筑，不存地板、不存队伍。
- 只放处理器时，链接目标要自己在地图上摆；交付说明里写清每个链接名对应什么方块、放在哪。
- 版本闸门：基线 **build 146**；用了新版本才有的方块/指令就在头部标注最低 build。

## 12. 交付前检查表

按顺序跑，任何一步红都别交付：

```bash
python mindustry-blueprint/tools/mlog.py check  my.mlog          # 语法/标签/未定义变量
python mindustry-blueprint/tools/mlog.py check  my.mlog --cost   # 最坏指令数、死代码
python mindustry-blueprint/tools/mlog.py ir     my.mlog          # 死存储（分 reported/slot/declaration）
python mindustry-blueprint/tools/mlog.py values my.mlog          # 常量分支、可证 null
python tools/mlogsim.py my.mlog --ticks 120 --trace out/t.csv --assert-last "chp < 1100"
```

- 静态检查约 2 条误报/块，当提示器；`values` 只对 4% 的块有信号，没有信号不等于没问题。
- 模拟器是**逻辑层 + 单位运动层 + 世界更新/天气 + 子弹命中**；波次、电力图、地形碰撞、真游戏 AI 仍要玩家实测。
- 交付时把“模拟器能证明的”和“需要玩家在游戏里验收的”分两栏写清楚。

## 13. 反模式清单

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 不 `ubind` 就 `ucontrol` | 静默无效 | 每轮先 `ubind` |
| `@dead` 用 `notEqual 1` 当“活着” | 死单位被留下 | `equal unit.dead? 1` 跳去重绑 |
| `ulocate` 放进条件分支 | 坐标未初始化，单位飞 (0,0) | 无条件放前面，每轮执行 |
| 用 `equal x null` 判空 | 0 也命中 | `strictEqual` |
| 自己加“留 30% 余量” | 判据偏离标准答案 | 按游戏机制下限 |
| 用理论速度推算“跑不到” | 结论常错 | 实测或查标准蓝图 |
| `jump 0 always` 空转 | 一个 tick 烧光 ipt | 等调用 `@time` 到期判定，期间做别的事 |
| 用 `wait 0.5` 等下一轮 | 等待期间处理器完全空转 | `op add cfg.timer @time 500`，用 `@time >= cfg.timer` 判定 |
| 普通处理器里读 `@clientUnit` / `@client` | 静默得到 null，分支永远不走 | 换 world processor，或改用游戏内可观测的实体/规则 |
| `sensor x core @copper` / `@hyper-processor` | 第三个参数是 `LAccess` 属性，物品/方块名读到 null，比较恒假 | 只用 75 个属性（`@x`、`@health`、`@totalItems`、`@itemCapacity`…）；`check` 报 WARN `sensor-not-a-property` |
| `write v @this "全文没出现过的名字"` | 静默空操作，跨周期存读永远不生效 | 先在任意语句里提到这个名字（`set`、`print`、`draw triangle` 都算）；`check` 会报 INFO |
| 把 `read v @this "slot"` 当成“按链接名读” | 字符串地址是处理器**变量**，链接要用数字下标 `read v @this 0` | 名字里带编号的会退化成链接名，别靠这个猜 |
| 以为 `ulocate` 建筑离得远就不给 | `outBuild` 条件是“射程内**或同队**”（`LExecutor.java:249-259`） | 同队核心/建筑多远都能拿到；只有异队超射程才是 null |
| 改一行不重算 `jump` | 跳到错的语句 | 交付前逐条数 |
| 把 `weatherset` 放微型处理器 | 整行静默消失 | 放 world processor |
| 在循环里每 tick `weatherset true` | 天气永不过期 | 只在需要时创建一次 |
| 无域名裸变量（`x`、`hp`、`t0`） | 与汇编器占位 `x` 冲突/重名 | 一律 `域.字段`：`tmp.x`、`unit.hp` |
| 用 `_` 或 camelCase 混写 | 同一项目两种风格 | 点分段，域内小写 |
| 用 `print` 当注释且不 flush | 缓冲 400 字符后截断 | 注释用 `#`，调试输出才 `print` |

## 14. 版本与兼容

- 基线 **build 146**（`v146`）；新方块/新指令在头部注明最低版本。
- `content ID` 是构造顺序号，mod 与版本都会影响；跨版本分享蓝图前先在目标版本里 `parse` 一遍。
- `@ipt` 随处理器型号变化；`--cost` 的折合秒数按 micro 算，换型号自己换算。
- 模拟器默认 v160.7 服务端（`out/_server160.jar` + `out/jre21`）；v146 缺 `LogicBlock.readable`，跨处理器按名读恒 `null`——别拿 v146 的结果判断跨处理器逻辑。

## 15. AI 生成标注（必须）

AI 生成的逻辑必须带署名，且署名**不允许去除**。

```
python tools/aigenerated.py sign    Logic/foo.mlog     # 写完就签
python tools/aigenerated.py verify  Logic/foo.mlog     # 交付前必验
python tools/aigenerated.py extract Logic/foo.mlog     # 看签名里带的注释与原始行号
python tools/aigenerated.py restore Logic/foo.mlog     # 把注释按锚点放回正文
```

- 署名落点：最后一条**语句的声明参数槽**里多带一个字符串，按顺序选槽：
  - 末尾 `end` 之前是无条件跳转 `jump N always <value>`（还没有第 4 个参数）→ 写进它的 compare 槽：
    `jump N always <value> "aigenerated:mlog:9e47003b6c89:<payload>"`，`end` 保留，跳转与行为不变；
  - 末尾是 `end`（或没有 `end`，先补一个）→ 用 `jump 0 always 0 "aigenerated:…"` 替换/收尾：
    `always` 从不读 value/compare，`jump 0` 与 `end` 一样把 `@counter` 置 0，行为完全一致；
  - 末尾跳转已经带第 4 个参数（如 `jump 5 always 0 true`）→ 不覆盖它，退回上一条的终止行写法。
  - 为什么必须占 compare 槽：`JumpStatement` 的字段是 `destIndex, op, value, compare`，游戏自己的
    `LAssembler.write(...)` 总输出 4 个参数，并把缺失的 compare 补成 `false`（`jump 0 always "…"`
    会变成 `jump 0 always "…" false`）；占 value 槽会被改写，占 `op`/`end` 的尾部多余 token 会直接丢。
- **注释也放进署名**：`<payload>` 是 base64url(zlib(JSON `[[原始行号, 语句锚点, 注释], ...]`))。
  交付文件正文里不再有 `#` 行，注释随代码进出游戏；`extract` 按原行号显示，`restore` 按
  语句锚点插回（标签行不算语句，所以重新标注后锚点仍成立）。
- 为什么不用尾部多余 token：`end "…"` 的多余 token 在 `LParser` 里就丢了，游戏重新
  序列化时签名不存在。也不要用普通注释（进游戏会被剥掉），不要在 `end` 后加 `set`
  （`end` 之后的语句会被 `LAssembler.write` 整段丢弃，且多一条指令会改 jump 偏移）。
- 哈希只覆盖**无注释正文**（签名 token、注释行、旧式标记先剥掉再算）：把注释挪进/挪出
  正文不会改 id；改真正的逻辑会 `FAIL ... body changed after signing`，要改就 `--force` 重签。
- `.msch` 存的是处理器源码，所以**先签 `.mlog` 再生成蓝图**，标记随源码进蓝图。
- `strip` 被策略拒绝（退出 2）；手工删 token 后 `verify` 必然失败，这类文件不要接收。
- **自动签名**：`tools/mlog.py gen` 默认先签再打包（`--source` 时把源文件也签好，`--logic` 时在内存里签），不用记得第二条命令；确需关闭用 `--no-sign`。已有签名且正文未改时保持原 id。

**一句话总结**：mlog 没有隐式上下文，没有异常，没有“差不多”——
要用什么先取什么，读不到就守卫，每个数字都要能追到源码或标准蓝图。
