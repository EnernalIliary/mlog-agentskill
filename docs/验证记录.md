## 本轮发现并修复

1. **`selftest` 没有归一化坐标**（真 bug，已修）：`mschgen.selftest` 用绝对 tile 坐标比较原蓝图与重建蓝图，
   于是平移被算成不一致，输出 **176/430**。改为按包围盒原点归一化后比较（`_norm`），现为 **430/430**。
   这与 S-05 的历史结论一致，说明当时修的是别处、`selftest` 没跟上。
2. **`gen` 会自动给源文件签名**：`mlog.py gen` 默认调用 `aigenerated.sign()`，会改写 `--source` 文件（追加/替换
   `jump 0 always 0 "aigenerated:..."`）。R-10/R-11 的实验里源文件被原地改过一次，属预期行为，文档已写。
3. **`itemTake` 首次转移受 `Time.time` 门控**：`ItemTakeI` 先 `timeoutDone(unit, transferDelay)`，单位刚 spawn 时
   `Time.time` 还不够大，单条 `itemTake` 会静默失败；必须循环重试（约 30–40 tick 后成功）。L2-08 的 5 格/9 格
   对照就是靠循环才复现的。
4. **`ucontrol stop` 不是刹车**：stop 后 120 tick 仍有约 0.1 tile 的残余位移（drag 衰减），断言里的“继续滑行”成立，
   但幅度很小，不能拿它当“立刻停住”。

## 2026-10-30 ipt 预算池与 wait 语义（L1-28..L1-31 新增）

## 2026-10-30 P5 第二刀：写前冲突检测（L2-47 新增）

作业是异步的（模型档可能等几十秒），等结果时玩家顺手改了代码，原来点「写入」会把改动静默覆盖。
这一刀在模组侧补上「投递那一刻的代码」基线：`JOB_ORIG["x,y"]`，两条投递路径都记（`jobSubmit()` / `jobSync()`），
写入前比对，不一致就拒绝一次，再点一次「写入」才算确认覆盖（`JOB_FORCE` 只放行一次）。
不做对话框是有意的：无头环境 `Core.scene` 为 null 会 NPE，而「拒绝一次 + 再点一次」在真机与测试里同一条路径。

| 断言 | 结果 | 证据 |
| --- | --- | --- |
| L2-47（新增）| PASS (E) | `MAICONFLICT:ok`（拒绝 → 放行一次 → 第三次又问 → 代码没动过不问）；端到端真 sidecar + 真 v160.7 处理器：投递 → `updateCode('set n 7' + \n + 'end')` → 第一次 `maiJobWrite` 返回「被改过」且代码未变，第二次「已写入」；摘要行 `job conflict gate: first write refused, second click overwrote`；`MAIDIAG:版本：0.10.1（游戏构建 160）` |

诚实缺口：只覆盖「单处理器 + 一次写入」；多处理器事务写入（一个作业 N 段代码、整体回滚）仍未做，

## 2026-10-31 P5 第三刀上半：事务写入核心（L2-48 新增）

一句话要写到一片处理器上时，之前只能一台一台点；中途某台失败，存档就停在一半新一半旧。
这一刀在模组侧把「N 台」做成一次事务，**不扩 sidecar 的作业契约**：每台一个作业（链接表 / 门禁 / 修复循环各自独立），
写入阶段整批预检 → 整批冲突 → 整批落盘快照（同一个 `batch`）→ 逐台 `configure`，任一台抛错按快照回滚已写的；
撤销也按批次整批还原（`undoBatchFromDisk()`）。

| 断言 | 结果 | 证据 |
| --- | --- | --- |
| L2-48（新增）| PASS (E) | `MAIWRITEMANY:ok 已写入 2 台（事务 1793382167907_b）：@0,0 @3,3`：真 v160.7 引擎里现放第二台处理器（探针结束时拆掉），整批写 2 台、两台代码都等于作业代码；`undo()` 返回「已回滚 2 台（事务 …）」且两台都回到写前代码；再把第二台换成 `configure` 抛错的假 build —— 第一台被回滚、返回「已回滚 1 台」 |

复跑：`python -X utf8 tests/mlogauxyou/run_ui_smoke.py` → EXIT=0（表格方法 18 个全 OK_SKIN、假表 102 行/格、
作业三路与冲突门禁仍全过、`MAIUNDO:ok` / `MAICONFLICT:ok` / `MAILLM:ok 82` / `MAIWRITEMANY:ok`）。

诚实缺口：这一刀**只有核心与探针，没有面板按钮** —— 多台一起投递需要面板同时轮询 N 个作业（下一刀）；
`writeMany` 只吃已经 done 的作业结果，不负责投递；回滚走 `updateCode`（只还原代码，不还原链接表，
链接表本来就是各台自己的）；联机下服务端拒绝写入时的「无权限」提示仍未做。
