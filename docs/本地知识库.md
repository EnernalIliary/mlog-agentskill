# 本地知识库（tools/kb.py）

> 给 mlog 工具链配的离线检索库：把仓库里的规范、SKILL、工具源码切成块，做**向量 + 全文混合召回**，再用 cross-encoder 重排。
> 目的：让“查一条规则/一个命令/一处源码”从“翻文件 + 猜关键词”变成一次带出处的检索，减少每轮塞进上下文的原文。

当前状态（2026-10-22）：**4467 块 / 48 个文件**，索引在 `out/_kb/kb.sqlite3`。

---

## 1. 它解决什么

- 规范、SKILL、REFERENCE、工具源码加起来几十万字，全塞进上下文不现实。
- 关键词搜索（grep）只能命中字面；问“处理器变量怎么跨处理器读写”时，`read @this`、`optionalVar`、`跨处理器` 分散在多个文件。
- 这套库把**语义相近**和**字面命中**两路召回合并，再按“这段能不能回答这个问题”重排，返回带 `path:start-end` 的片段，可直接引用/核对。

---

## 2. 语料（收什么，不收什么）

显式清单（`DOC_FILES`，8 个文件）：

| 文件 | 用途 |
|---|---|
| `README.md` | 仓库总览 |
| `Logic/逻辑代码规范.md` | 命名、结构、坐标、边界、反模式 |
| `mindustry-blueprint/SKILL.md` | 工具链主手册（命令、自检、模拟器） |
| `mindustry-blueprint/REFERENCE.md` | 指令/方块/校准数字参考 |
| `mindustry-blueprint/EMULATOR-CROSSCHECK.md` | 模拟器与真实引擎的差异记录 |
| `tools/README.md` | 工具索引与用法 |
| `dsh-preset-mlog/README.md` | DSH 预设说明 |
| `rules/README.md` | 静态规则库说明 |

代码（`CODE_GLOBS`）：`tools/*.py`、`tests/run_tests.py`。

排除目录：`__pycache__`、`out`、`.git`、`assetsraw`、`Mindustry-Source`、`Arc-Source`。
**不带** `.dsh/skills/` 下的副本（和 `mindustry-blueprint/` 内容重复），也不带 `Logic/` 里的个人程序。

改语料 = 改 `tools/kb.py` 顶部的 `DOC_FILES` / `CODE_GLOBS`，然后重建索引。

## 3. 切块

- **Markdown**：按 `#`~`####` 标题切；每块前加一行 `# <标题>` 作为上下文；单块超过 **1400 字符**按行再切（`_split_long`）。
- **代码**：按顶层 `def` / `class` / `@decorator` 切；单块超过 **120 行**再切。
- 每块记录 `path` / `start` / `end`（原始行号）/ `kind`（doc|code）/ `heading`。

行号是对原始文件算的，所以检索结果可以直接 `read path:start-end` 核对。

---

## 4. 索引

单个 SQLite 文件：`out/_kb/kb.sqlite3`（可用 `KB_DIR` 改目录）。

- `chunks(id, path, start, end, kind, heading, text, vec)`
  - `vec`：`bge-small-zh-v1.5` 的 512 维 float32（numpy `tobytes()`）。
- `fts`：FTS5 虚表，`tokenize='trigram'`，索引 `text/heading/path`；中文不依赖分词器，三元组直接匹配。
- 检索时全量取块做余弦（几千块规模足够快），FTS 走 `bm25()` 排序。

---

## 5. 检索管线

```
query
 ├─ 向量：embed(query) → 与所有块余弦 → 取前 candidates（默认 30）
 ├─ 全文：FTS5 MATCH → bm25 排序 → 取前 candidates
 ├─ RRF 融合：score += 1 / (60 + rank)
 ├─ （可选）cross-encoder 重排：bge-reranker-base 对前 30 块打分
 └─ 取 top-k（默认 6），返回 path:start-end + score + 片段
```

- `--no-rerank` 跳过 cross-encoder（快，但排序质量下降）。
- 重排失败只打印 `rerank skipped: ...` 并回退到 RRF 分数，不会让查询失败。
- `--kind doc|code` 限定语料类型。

`search()` 的默认参数：`k=6`、`candidates=30`、`rerank=True`、RRF 常数 `60`。

---

## 6. 模型与依赖

| 用途 | 模型 | 说明 |
|---|---|---|
| 向量 | `BAAI/bge-small-zh-v1.5` | 512 维，中文短文本检索，CPU 可跑 |
| 重排 | `BAAI/bge-reranker-base` | cross-encoder，首次加载/首次查询较慢 |

- 运行时：`fastembed`（onnxruntime，本地推理，无 API）。
- 依赖目录：`out/_kblibs`（Python <3.12 时用 `out/_kblibs311`）。
- 模型缓存：`out/_kbmodels`。
- 可覆盖的环境变量：`KB_DIR`、`KB_LIBS`、`KB_MODELS`、`KB_EMB_MODEL`、`KB_RERANK_MODEL`。

两者都在 `out/` 下，不入库；换机器要重下（约几百 MB）。

## 7. 安装

```powershell
cd <repo>

# 1) 依赖装到独立目录，避免污染全局 Python
python -m pip install --target out/_kblibs fastembed

# 2) 首次建库（会下载模型；国内建议走镜像）
$env:HF_ENDPOINT = "https://hf-mirror.com"
python tools/kb.py build
```

模型下载完成后可离线使用。装依赖时注意 Python 版本与 `_LIBS_DEFAULT` 的对应关系（3.11 → `out/_kblibs311`）。

## 8. 用法

```powershell
# 建库/重建（会删旧库）
python tools/kb.py build

# 检索（默认 6 条，带重排）
python tools/kb.py search "read @this 处理器变量怎么写"

# 只要文档 / 只要代码；不重排（快）
python tools/kb.py search "战斗 tick" --kind doc
python tools/kb.py search "LAssembler.write" --kind code --no-rerank

# 多取几条
python tools/kb.py search "蓝图链接坐标" -k 10

# 索引统计
python tools/kb.py stats
# {"chunks": 4467, "files": 48}

# MCP stdio 服务（给 DSH/其它客户端接）
python tools/kb.py serve
```

输出示例：

```
[1] tools/mlogir.py:259-260  score=4.5625
...
```

`score` 是重排分（未重排时是 RRF 分）。

## 9. 接入 DSH（MCP）

在 DSH profile 的 `cordis.patch.yml` 里加一个 `@deepseek-ai/dsh-mcp-client` 行（desktop profile 用 `~/.dsh/profiles/default/cordis.patch.yml`）：

```yaml
- id: mcp-kb
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: kb
    transport: stdio
    command: 'C:\Users\<you>\AppData\Local\Programs\Python\Python311\python.exe'
    args: ['<repo>\tools\kb.py', 'serve']
    env:
      HF_ENDPOINT: 'https://hf-mirror.com'
```

- 改完**重启 DSH**。
- 首次查询会加载两个模型（~20–25 秒），之后常驻内存。
- 会话里以 `kb_search` 工具暴露（`query`、`k`、`kind`）。
- 若索引重建过，`serve` 进程要重启才会读到新库（它按需打开 sqlite，但模型/连接是常驻的）。

## 10. 维护

- **改完文档/工具源码后重建**：`python tools/kb.py build`。当前规模一次约 1 分钟（含向量化）。
- 想加语料：改 `DOC_FILES`/`CODE_GLOBS`；想排除：改 `EXCLUDE_DIRS`。
- 调块大小：Markdown `1400` 字符、代码 `120` 行（`_section_chunks` / `_split_long`）。
  - 块太大 → 检索命中但片段噪声多、重排成本高；
  - 块太小 → 语义不完整、跨段问题召回差。
- 重复内容：不同文件里的同一段会各成一块；已在语料层去掉 `.dsh` 副本，其余重复靠重排压制。

## 11. 排障

| 现象 | 原因 / 处理 |
|---|---|
| `UnicodeEncodeError: 'gbk' ...` | Windows 控制台默认 GBK；脚本已把 stdout/stderr 设为 UTF-8，仍报错时先 `$env:PYTHONIOENCODING='utf-8'` |
| `TextEncodeInput must be Union[...]` | MCP 的 stdin 被按 cp936 解码，中文 query 变代理字符；`serve` 已 `reconfigure(encoding='utf-8')`，旧版本需升级 `kb.py` |
| 模型下载卡住/失败 | 设 `HF_ENDPOINT=https://hf-mirror.com`；或手动把模型放进 `out/_kbmodels` |
| `rerank skipped: ...` | 重排模型加载失败（缺依赖/内存不足），查询仍返回 RRF 结果 |
| `stats` 显示 0 | 还没 build，或 `KB_DIR` 指到了别处 |
| 第一次查询 20s+ | 正常：两个 ONNX 模型首次加载；后续查询毫秒级 |
| 索引和文档不一致 | 重建后重启 `serve`/DSH |

内存：两个模型常驻约 1 GB 以内（CPU）。机器吃紧时用 `--no-rerank` 或换更小的重排模型。

## 12. 设计取舍

- **为什么不用向量数据库**：语料只有几千块，SQLite + numpy 暴力余弦足够快，少一个服务、少一份状态。
- **为什么中文用 trigram**：FTS5 默认分词对中文不友好；trigram 对“`@counter`”“`read @this`”这类符号串也稳。
- **为什么保留 BM25**：向量对专有名词/指令名不敏感，BM25 正好补字面命中。
- **为什么重排**：混合召回的前 30 条里常混入“提到了关键词但没回答问题”的段，cross-encoder 能明显改善 top-3。
- **为什么放 `out/`**：模型和索引都是可再生产物，不入库、不进公开仓。
