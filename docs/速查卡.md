# mlog 速查卡（一页）

> 每条结论都挂着 [docs/断言表.md](断言表.md) 的断言 id。`python tests/docsig/run_docsig.py` 会校验这些 id
> 真实存在：id 写错、或引用了断言表里没有的 id，都会 FAIL。改结论的顺序是**先改断言表、再改这张卡**。

## 1 我现在能用这个单位吗（L2-18 L2-19 L2-20 L2-21）

- 判据：`@dead == 0` 且（`@controller == @this` 或 `@controller == @unit`）
- `@dead` 一条覆盖两种失败：单位已死、`@unit` 是 null（压根没绑到）
- `@controlled` **不能**代替 `@controller` 判「是不是我在控」：别的处理器在控也返回 1
- 检查要放在 `ucontrol` **之前**：`ucontrol` 一执行就抢占控制权，不是「抢了会失败」

```mlog
ubind @flare
sensor d @unit @dead
jump 6 notEqual d 0
sensor c @unit @controller
op equal mine c @this
op equal free c @unit
op or ok mine free
```

## 2 radar / uradar 没有「数量」参数（L2-17）

- 7 个槽：`radar <目标1> <目标2> <目标3> <排序依据> <参照建筑> <排序方向> <输出>`
- 三个 target 槽是**叠加筛选**（AND），不是三个候选结果
- 第 6 槽是排序**方向**（布尔）：写 `5` 只是「非零 = 真」，不是「取 5 个」
- 整条语句只有**一个输出**：1 个单位或 null；雷达结果还有 30 tick 缓存
- `uradar` 同样 7 槽，第 6 槽是死槽；少写一个占位符 → 目标变量被当成方向

```mlog
radar enemy any any distance turret1 1 target
```

## 3 文本 token 序 = Java 字段声明序（L1-27）

- 读文档签名要按**字段声明序**，不要按 `build(LAssembler)` 的传参序
- 典型：`getblock` 真序是 `layer result x y`；写成 `<result> <x> <y> <layer>` 是「数目对、顺序错」→ 静默错位

## 4 status：第一槽是布尔（L2-22 L1-23 L1-24）

- 形状：`status <true|false> <effect> <unit> <duration>`；`false` = 施加，`true` = 清除（源码字段名是 `clear`）
- 写 `status apply ...` 或 `status clear ...` 都会被当成未定义变量 = false ⇒ **两条其实都在施加**
- 效果名 v160 三种写法都行：裸名 `wet`、`@status-wet`、变量里存 `@status-wet`；拼错静默无效（v159.3 同样）

```mlog
ubind @flare
status false wet @unit 20
```

## 5 控制租约 600 tick（L2-25 L2-15）

- 单位：最后一次 `ucontrol` 之后 600 tick（10 s）内没有新的 `ucontrol` → 自动脱离控制
- 炮台：`control shoot` 一次后约 600 tick 停火
- 所以「开局发一条指令就完事」的程序会自己失效；要持续控制就得每轮重发

## 6 链接名（L2-12 L2-13 L2-130）

- 链接半径 10 格：9 格、10 格成，11 格败
- 链接名 = 方块名**最后一段** + 序号：`silicon-arc-furnace` → `furnace1`
- 名字本身带连字符（`phase-fabric`）只能靠序号引用，别写 `phase-fabric1`
- 名字对不上（没连上、或拼错）= 该槽取 null、语句静默无效；静态检查报 `link-name-not-bound`
- **硬要求**：链接名只能是「方块名最后一段 + 1 基序号」。写 `sw1`（只是 `switch` 的开头）读档时会被**整名改掉**成 `switch1`，代码里的 `sw1` 恒 null —— 两个开关曾经就这样全死（m00622）
- 基名对照：`switch`→`switch1`、`message`→`message1`、`world-cell`→`cell1`、`memory-bank`→`bank1`、`core-shard`→`shard1`（**不是** `core1`）、`silicon-arc-furnace`→`furnace1`
- 静态检查：`link-name-base-mismatch`（真能绑上的基名一律不报）

```mlog
# 对：基名 + 序号，读档不会被改名
sensor run switch1 @enabled
read n cell1 0
write n bank1 1 0
```

## 7 wait 与 ipt 预算（L1-28 L1-29 L1-30 L1-31）

- 预算是**额度池**，不是每 tick 重发的票：余额跨 tick 累积、上限 5×ipt、超出削顶（丢弃，不延迟）
- 单 tick 上限：micro 10 条 / logic 40 条 / hyper 125 条（ipt = 2 / 8 / 25）
- `wait` 的粒度是 1 tick：`wait 0.001` 与 `wait 0.0166` 完全等价，都只停 1 tick；单位是**真实秒**，低帧率下同一个 wait 跨的 tick 数会变少
- `wait 0` 不睡、不卡死，但**一点空转都不省**：吞吐与不写这条 wait 完全相同
- 想攒满突发：停 5 tick（0.0833 s）就到顶，`wait 0.08` 是「攒满」专用值，不是「等待」的通用值
- 攒满后一个 tick 能连跑 5×ipt 条 ⇒ 原子快照/事务：几条 read/op 在一个 tick 里写完，外部读不到中间态
- 反模式：为攒而攒（平均吞吐掉一个数量级）、拿 `wait` 当定时器、把事务写得超过 5×ipt 条

```mlog
wait 0.08
read a cell1 0
read b cell1 1
op add s a b
write s cell1 2
```

- 多处理器降频轮询：`wait 0.5`，并给每台不同初相位错开唤醒（别让所有处理器同一 tick 醒来）

## 8 `equal` / `notEqual` 里的 null 就是 0（L1-32）

- `equal X 0` 在 X 是 null 时判**真**：null 的 `num()` 是 0（和 L1-07 同一条规则）；「从未赋值」「链接名绑不上」「读不到」都是 null
- 所以判「开关是不是 ON」别写 `jump L lessThan X 1`：X 为 null 时那是真 ⇒ 一个断掉的开关被当成 ON，后面全错
- 稳妥写法 `op sub V 1 X`：ON(1)→0、OFF(0)→1、null→1 —— 只有真 ON 才得 0（三例实测：`<scratch>/mg4/ui/_eqA.mlog` / `_eqB.mlog` / `_eqC.mlog`）
- 根因：`equal` 只在**两侧都是对象**时才比对象（`LExecutor.java:863-868`），其余按数值比；对象 null 的 `num()` 是 0（`LVar.java:56-58`）⇒ 它天生分不清 null 与 0；要分辨用 `strictEqual`（`:858-859`，先要求两侧 `isobj` 相同）

```mlog
sensor x switch1 @enabled
op sub v 1 x
# v == 0 才是真 ON；x 是 null 时 v == 1
```

## 9 世界处理器与跨台部署（L1-33 L1-34 L1-35 L1-36 L2-131）

- 世界处理器默认 `ipt=8`，首行写 `setrate 1000` 后 **1000 条/tick = 60,000 条/s/台**（micro 120、hyper 1,494，都是 1 条/tick 量级）
- 调速语句**只能写 `setrate 1000`**：界面里显示成 `ipt = `，那是提示文本；照抄成 `ipt = 1000` 会被静默丢弃，ipt 一动不动
- `setrate` 是 privileged：写在 micro / logic / hyper 上**不报错也不生效**（仍是 2 / 8 / 25 条/tick）
- 单台编译后**最多 1000 条**（下标 0..999，第 1001 条起被丢）：跨台拆分里每条 `read`+`jump` 哨兵都占位，超了在编译期被静默截断 ⇒ 被截断的块永远不写 flag、下游永久自旋、结果全 0（症状是「全零」不是「报错」）
- 延迟**看 DAG 深度，不看总条数**：`write` 后对端 ≤1 tick 可见；块按 tile 顺序更新时一条链能在同一 tick 级联（实测 depth 11 与 depth 26 都 3 tick 出全部结果）
- 半径墙消失：世处 `range = Float.MAX_VALUE`（hyper 只有 336 像素）⇒ 大网络不必分蓝图/中继

```mlog
setrate 1000          # 只有世处生效；iprocessor 上能写但没效果
read wf3 flagcell 0   # 跨台依赖：先读哨兵
jump @counter equal wf3 0   # 没到就自旋等（这 2 条要算进 1000）
# …本块主体…
write out cell5 0
write 1 flagcell 0
end
```

- 反模式：把 `ipt = 1000` 当调速；在 micro 上写 `setrate` 以为加速了；按「总条数 ÷ ipt」估算延迟；跨台块写满 1000 不留哨兵位

## 10 闭环与一次性块的三条语义（L1-37 L1-38 L1-39）

- `end` **不是停机**：它等价于「跳回第 0 条」，同一 tick 内还会继续跑，直到 ipt 预算耗尽。要真停写 `stop`；要驻留写 `label halt` / `wait 0` / `jump halt always`
- 一次性块（装载器、驱动器）必须自己驻留，否则每 tick 从头重跑 —— 外部看到的状态会被覆盖成初值（闭环里的症状：token 永远是种子值）
- `op rand` 只有 1 个操作数：`op rand r 1` 是 [0,1)，`op rand r 0 1000` 恒 0（多余 token 被忽略）
- 采样 = 预置 r + 阈值累积搜索：`op mul thr r tot`，然后对每个 j 一条 `op add cum cum p_j` + `jump next lessThan cum thr`（共 2V+2 条）
- 跨台握手用**单调相位号**，别用 0/1 边沿：写是立刻可见的、对方随时可能采样，边沿会被跳过 ⇒ 互等死锁

```mlog
# 一次性块驻留：别指望 end 停机
label boot
read f cell1 273
jump boot equal f 1
# …只跑一次的装载…
write 1 cell1 273
label halt
wait 0
jump halt always
```

```mlog
# 单调相位握手：写数据 → 写相位号（只增）→ 等完成计数跟上
op add t t 1
write r cell1 259
write t cell1 257
read d cell1 258
jump @counter lessThan d t
```

- 反模式：拿 `end` 当停机；一次性的驱动器不驻留（状态被每 tick 覆盖）；`op rand r 0 1000`；用 0/1 边沿做跨台握手
